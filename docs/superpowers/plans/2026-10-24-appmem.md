# appmem Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A macOS terminal tool that shows memory use grouped per app, with a tree view, and lets the user quit an app or terminate a process.

**Architecture:** One binary crate with a library inside it (`src/lib.rs`) so the logic can be tested. Pure, platform-independent modules handle attribution, grouping, UI state and terminate policy, and are unit-tested with fake data. A macOS-only `collector` module reads processes and system stats over FFI (`libc` plus a few hand-declared symbols). The `ui` module renders with ratatui and runs a synchronous event loop that polls with a timeout. No async runtime.

**Tech Stack:** Rust stable, `ratatui` (crossterm backend, used through `ratatui::crossterm`), `libc`, `plist`. Only these three runtime dependencies, and no dev-dependencies beyond std.

**Spec:** `docs/superpowers/specs/2026-10-24-appmem-design.md`

## Global Constraints

- macOS only; primary target Apple Silicon. Minimum macOS: 12 (Monterey). This is the builder's call, documented in the README.
- Stable Rust; dependencies few and light; **no async runtime**; no `clap` (hand-parse args).
- No `sudo` needed for normal use.
- Self footprint target: **under ~15 MB resident**, negligible CPU at idle refresh.
- Default refresh **every 2 seconds**, `--interval <seconds>` to change it.
- Must work in an **80×24** terminal; respect `NO_COLOR`.
- Per-process memory = `ri_phys_footprint` (`proc_pid_rusage`, `RUSAGE_INFO_V4`).
- Pressure from `kern.memorystatus_vm_pressure_level`: 1 = normal, 2 = warn, 4 = critical.
- Swap from `vm.swapusage`; total from `hw.memsize`.
- Terminate is SIGTERM only, **never SIGKILL**.
- Code, comments, README, commit messages in English; commits follow Conventional Commits and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- License MIT; crate name `appmem`.

## Review Focus

1. **A process exits, or can't be read, between listing and reading** (`EPERM`, `ESRCH`, path unavailable). Expected: it is skipped, or counted as unreadable, with no panic and no 0-byte rows. Tests: Task 3 `unreadable_procs_are_not_listed`, Task 4 `snapshot_survives_dead_pid`.
2. **The footprints add up to more than "used"** (shared memory is counted twice). Expected: the System remainder saturates at 0, with no underflow panic and no huge number. Test: Task 3 `remainder_saturates_at_zero`.
3. **PID reuse between the confirm prompt and `y`.** Expected: the tool re-checks that the PID still has the same executable path before signalling, and refuses otherwise. Test: Task 7 `refuses_when_pid_now_points_elsewhere`.
4. **Tiny or resized terminal** (e.g. 40×10, or a height smaller than the list). Expected: no panic, the list scrolls to keep the selection visible, long names are truncated. Test: Task 8 `renders_in_tiny_terminal`.
5. **Long or Unicode app names and paths with spaces** ("Google Chrome.app", emoji). Expected: correct bundle detection and truncation by display width, never by bytes. Tests: Task 2 `bundle_path_with_spaces`, Task 8 `truncates_wide_names`.

### Task 2: Attribution rules

**Files:**
- Create: `src/attribution.rs`

**Interfaces:**
- Consumes: `ProcInfo` (Task 1)
- Produces:
  - `#[derive(Debug, Clone, PartialEq, Eq, Hash)] pub enum Bucket { App(PathBuf /* outermost .app bundle path */), Simulator, CommandLine, System }`
  - `pub fn classify_path(path: &Path) -> Option<Bucket>`: rules 1, 2 and 4 of the spec. Returns `Some(System)` for system prefixes, `Some(Simulator)` for simulator paths, `Some(App(bundle))` for an outermost `.app`, and `None` otherwise.
  - `pub fn attribute(proc: &ProcInfo, responsible_path: Option<&Path>, current_uid: u32) -> Bucket`: the full rule order 1→6.

Rule order inside `attribute` (from the spec):
1. Own path under `/System/`, `/usr/`, `/bin/`, `/sbin/`, `/Library/Apple/` → `System`.
2. Own path contains `.simruntime/` or `/CoreSimulator/`, or the outermost-or-inner bundle is `Simulator.app` → `Simulator`.
3. If `responsible_path` is `Some` and `classify_path(responsible)` gives `App` or `Simulator`, use it.
4. The outermost `.app` in the own path → `App`.
5. `uid == current_uid` → `CommandLine`.
6. Otherwise → `System`.

A process with `path: None` skips rules 1, 2 and 4.

Note for the implementer: with rule 3, a shell or CLI started inside Terminal is attributed to Terminal.app, and `rust-analyzer` started by Zed is attributed to Zed. This is intended; it is what Activity Monitor does.

### Task 3: Grouping and totals

**Files:**
- Create: `src/grouping.rs`

**Interfaces:**
- Consumes: `Snapshot`, `ProcInfo`, `SystemStats` (Task 1); `Bucket`, `attribute` (Task 2)
- Produces:
  - `pub struct AppMeta { pub name: String, pub bundle_id: Option<String> }`
  - `pub trait BundleInfo { fn meta(&mut self, bundle: &Path) -> AppMeta; }`
  - `#[derive(Debug, Clone, PartialEq)] pub struct Group { pub key: Bucket, pub name: String, pub bundle_id: Option<String>, pub procs: Vec<ProcInfo> /* sorted desc by footprint */, pub total: u64, pub estimated: bool }`
  - `pub fn build_groups(snap: &Snapshot, bundles: &mut dyn BundleInfo) -> Vec<Group>`

Rules:
- Look up the responsible process's path by finding `responsible_pid` in `snap.procs`. If it is missing, or the same as the process's own PID, pass `None`.
- Processes with `footprint: None` are not listed, and their memory falls into the remainder.
- Group names: `App(b)` → `bundles.meta(b).name`; `Simulator` → `"Simulator"` with bundle id `"com.apple.iphonesimulator"`; `CommandLine` → `"Command-line tools"`; `System` → `"System"`.
- System group: `total = readable system footprints + remainder`, where `remainder = used.saturating_sub(wired).saturating_sub(sum of ALL listed footprints)`, and `estimated = remainder > 0`. The System group is always present.
- Sort: groups descending by `total`, **System always last**. Within a group, processes are sorted descending by footprint, with ties broken by PID ascending.

  - `groups_chrome_helpers_together`: 3 Chrome procs of 100, 200 and 300 MB give one group `"Google Chrome"`, total 600 MB, with processes ordered 300, 200, 100.
  - `system_is_last_even_when_biggest`: System 3 GB and Chrome 1 GB give `groups.last().key == Bucket::System`.
  - `remainder_adds_to_system`: `used` 6 GB, `wired` 1 GB, listed 4 GB of which 0.5 GB is system gives System total 0.5 + 1.0 = 1.5 GB, `estimated == true`.
  - `remainder_saturates_at_zero`: listed footprints 9 GB with `used` 6 GB give System total = readable system only, `estimated == false`.
  - `unreadable_procs_are_not_listed`: a proc with `footprint: None` appears in no group's `procs`.
  - `responsible_lookup_uses_snapshot`: a CLI proc with `responsible_pid` pointing to a Zed proc in the same snapshot goes into Zed's group.

### Task 4: macOS collector

**Files:**
- Create: `src/collector/mod.rs`, `src/collector/ffi.rs`, `src/collector/bundle.rs`, `tests/collector_macos.rs`

**Interfaces:**
- Consumes: `Snapshot`, `ProcInfo`, `SystemStats`, `Pressure` (Task 1); `BundleInfo`, `AppMeta` (Task 3)
- Produces:
  - `pub trait Collector { fn snapshot(&mut self) -> std::io::Result<Snapshot>; }`
  - `pub struct MacCollector` + `MacCollector::new() -> MacCollector` (resolves the `responsibility_get_pid_responsible_for_pid` symbol once through `dlsym(RTLD_DEFAULT, …)`, stored as `Option<extern "C" fn(i32) -> i32>`)
  - `pub fn proc_path(pid: i32) -> Option<PathBuf>` (also used by Task 7)
  - `pub struct PlistBundles` implementing `BundleInfo` with a `HashMap<PathBuf, AppMeta>` cache. It reads `Contents/Info.plist` through `plist::Value::from_file`, and the name comes from `CFBundleDisplayName`, then `CFBundleName`, then the folder name without `.app`. `bundle_id` comes from `CFBundleIdentifier`.

How to read each value:
- PIDs: `proc_listallpids` (size the buffer by calling it with null first, then add 20% headroom).
- uid, ppid, name: `proc_pidinfo(pid, PROC_PIDTBSDINFO, …)` → `libc::proc_bsdinfo` (`pbi_uid`, `pbi_ppid`, `pbi_name`, falling back to `pbi_comm`).
- path: `proc_pidpath` with a buffer of `PROC_PIDPATHINFO_MAXSIZE` (4096).
- footprint: `proc_pid_rusage(pid, RUSAGE_INFO_V4 /* 4 */, &mut rusage_info_v4)`. Declare `rusage_info_v4` in `ffi.rs` with `#[repr(C)]`, copying the field layout from `<sys/resource.h>` in the macOS SDK (`xcrun --show-sdk-path`). Only `ri_phys_footprint` is read.
- If any per-PID call fails, set that field to `None`; never abort the whole snapshot.
- Stats: `hw.memsize`, `hw.pagesize`, `kern.memorystatus_vm_pressure_level`, `vm.swapusage` (`xsw_usage`, read `xsu_used`) through `sysctlbyname`. Read `host_statistics64(mach_host_self(), HOST_VM_INFO64, …)` into `vm_statistics64`, then compute `wired = wire_count × page`, `used = (internal_page_count − purgeable_count + wire_count + compressor_page_count) × page`.
- `current_uid = libc::getuid()`, `self_pid = std::process::id() as i32`.

### Task 7: Terminate and quit

**Files:**
- Create: `src/terminate.rs`

**Interfaces:**
- Consumes: `Snapshot`, `ProcInfo` (Task 1); `Group`, `Bucket` (Tasks 2–3); `proc_path` (Task 4)
- Produces:
  - `pub enum Action { Terminate { pid: i32, name: String, path: Option<PathBuf>, footprint: u64 }, Quit { name: String, bundle_id: String } }`
  - `pub fn protected_pids(snap: &Snapshot) -> HashSet<i32>`: `self_pid` and every ancestor through `ppid` up to, but excluding, pid 1.
  - `pub fn plan_terminate(proc: &ProcInfo, group: &Group, snap: &Snapshot) -> Result<Action, String>`
  - `pub fn plan_quit(group: &Group, snap: &Snapshot) -> Result<Action, String>`
  - `pub fn confirm_prompt(action: &Action) -> String`: `"Terminate Google Chrome Helper (Renderer) (pid 812, 820 MB)? y/N"` and `"Quit Google Chrome? y/N"`
  - `pub fn execute(action: &Action, current_path: impl Fn(i32) -> Option<PathBuf>) -> Result<(), String>`

Refusal messages are exact text and are shown in the status line:
- `"System processes can't be terminated"`: the group key is `System`.
- `"Not your process"`: `uid != current_uid`.
- `"That's appmem or the terminal running it"`: the PID is in `protected_pids`.
- `plan_quit` on `CommandLine` or `System`: `"This group can't be quit as a whole"`.
- `plan_quit` on a group that contains a protected PID: `"That's appmem or the terminal running it"`.
- `plan_quit` with no `bundle_id`: `"Can't identify this app to quit it"`.
- `execute` for `Terminate`, when `current_path(pid) != action.path`: `"Process already exited"`.

Execution: `Terminate` uses `libc::kill(pid, SIGTERM)`, and `ESRCH` maps to `"Process already exited"`. `Quit` runs `std::process::Command::new("/usr/bin/osascript").args(["-e", &format!("tell application id \"{bundle_id}\" to quit")])`. On a non-zero exit, return the first line of stderr. A `-1743` in stderr is the Automation permission being denied: in that case return `"Allow appmem's terminal in System Settings → Privacy & Security → Automation"`. Reject a bundle ID containing `"` or `\` before building the script.
